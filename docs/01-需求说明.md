# 胶片管理网站 — 需求说明

> 版本：v1.0（定稿）
> 最后更新：2026-11-07

## 1. 项目定位

一个**单用户私用**的胶片（胶卷）管理网站，部署在自己的服务器上，用于记录和查询胶卷从购入到拍摄完成的完整信息。

不是社区产品，不是库存商业管理软件，**不做分享功能**——需要分享时用户自己截图即可。

## 2. 用户与设备

| 项 | 说明 |
|---|---|
| 用户 | 只有一个人（本人） |
| 主力设备 | 安卓手机、鸿蒙手机、苹果手机、折叠屏 |
| 次要设备 | 电脑（偶尔） |
| 部署 | 自有服务器，通过 HTTPS 访问 |

## 3. 核心使用场景

### 3.1 拍摄前：建档

用户买了胶卷（通常**一盒多卷**），需要把每一卷录入系统。

- 胶卷外包装有**商品条形码**（EAN/UPC），可据此获得胶卷型号等基础信息
- 每卷胶卷上贴有用户自己打的**唯一编号条码**（二维码或一维码），如 `KG2T001`
- 录入方式优先级：**扫码 > 手动输入**
- 一盒多卷时，扫或输入**第一卷**之后即可**批量建档**多卷——除编号递增外没有任何差异

### 3.2 拍摄中：记录进度

**这是最高频的操作，必须极快。**

- 用户**不做逐张记录**，绝大多数时候只记录「当前拍到第几张了」
- 支持**回填过去某个时间点**的进度（事后补录），不要求实时
- **偶尔**记录某一张的某些信息（如光圈、快门、备注），属于锦上添花，不做强制
- 可以接受网络中断，事后补录即可

### 3.3 拍摄后：查看

- 快速查看某一卷的基础信息、当前进度、历史记录
- 页面设计需**适合手机截图**：留白足、字号大、不依赖悬停交互

## 4. 胶卷编号体系（系统的地基）

### 4.1 编码结构

```
K   G   2   T   001
│   │   │   │   └── 序号：3 位起（001），超过 999 自动升为 4 位
│   │   │   └────── 画幅：T=135  M=120  S=页片  P=110  X=其他
│   │   └────────── 感光度码：见 4.2
│   └────────────── 系列：品牌内唯一（K 下的 G = Gold）
└────────────────── 品牌：K=Kodak  F=Fujifilm  I=Ilford  A=Agfa  L=Lomography  C=CineStill …
```

**前 4 位（品牌 + 系列 + 感光度 + 画幅）= 型号唯一键（prefix）**，在系统中作为唯一索引。拿到一个编号即可反向确定是哪款胶卷。

### 4.2 感光度编码规则

规则：`v = ISO / 100`，`1–9` 用数字，`10–35` 用 `A–Z` 顺延。

| ISO | 码 | ISO | 码 | ISO | 码 |
|---|---|---|---|---|---|
| 100 | `1` | 800 | `8` | 1600 | `G` |
| 200 | `2` | 900 | `9` | 3200 | `W` |
| 400 | `4` | 1000 | `A` | 3500 | `Z` |

**已知边界与处理约定：**

| 情况 | 处理 |
|---|---|
| 非整百 ISO（160、125、50、64、320…） | 使用**小写字母例外码**，见下表 |
| ISO > 3500（如 6400） | 主规则溢出，同样走例外码表，待补充 |
| ISO < 100 | `0` 位空置不用 |

**例外码表（小写，与主规则大小写区分，不冲突）：**

| ISO | 例外码 | ISO | 例外码 |
|---|---|---|---|
| 25 | `a` | 160 | `d` |
| 50 | `b` | 320 | `e` |
| 64 | `c` | 125 | `f` |

示例：`KPdT` = Portra 160 135；`KFfT` = Fuji 125 135。

### 4.3 解析示例

| 编号 | 解读 |
|---|---|
| `KG2T001` | Kodak Gold 200 · 135 · 第 1 卷 |
| `KG2T005` | Kodak Gold 200 · 135 · 第 5 卷 |
| `KG2M002` | Kodak Gold 200 · 120 · 第 2 卷 |
| `KPdT010` | Kodak Portra 160 · 135 · 第 10 卷 |

## 5. 功能清单

### 5.1 胶卷库（型号级）

- 通过**商品条形码**绑定胶卷型号；一个型号可绑定多个条码
- 无条码的胶卷（分装卷、散装）可手动选择型号
- 型号信息：品牌、系列、名称、ISO、画幅、标称张数、工艺（C-41/E-6/BW）、色彩类型
- 支持 CSV 导入导出

### 5.2 建档（胶卷级）

- 扫码 / 手输编号 → 自动识别型号
- 单卷建档 / **批量建档**（一盒多卷，编号递增）
- 批量建档时做冲突检测：跳过插空 或 顺延到最大号之后
- 可选记录：购入日期、单价、来源、储存位置、有效期
- 可生成并打印编号二维码标签

### 5.3 拍摄进度记录（核心）

- **记一笔**：记录「拍到了第几张」，2 秒完成
- 默认时间 = 现在，可选**回填过去的时间**
- 快捷增量：`+1 +2 +5 +10`，也可直接输入目标张数
- 可选附带：机身、镜头、备注
- 当前进度 = 所有进度快照中的最大值
- 进度快照可编辑、可删除

### 5.4 单张注解（辅助，非核心）

- 针对某一具体张号记录：光圈、快门、EI、曝光补偿、镜头、地点、备注、配图
- **所有字段均可空**，允许只写一句备注
- 与进度记录完全解耦

### 5.5 状态流转

```
未拆封 unopened → 已装机 loaded → 部分使用 partial → 已拍完 exposed
                                                    ↓
                            已冲洗 developed → 已扫描/归档 archived
另有：作废 void / 丢失 lost
```

冲洗、扫描、归档环节**可全部跳过，不阻塞拍摄记录**。

### 5.6 相机与镜头库

- 机身：品牌、型号、卡口、备注
- 镜头：品牌、型号、卡口、焦段、最大光圈、备注
- 初始预置：`Canon EOS 30V`、`Canon EF 50mm F1.8`

### 5.7 详情与检索

- 单卷详情：编号 → 型号卡 → 进度条 → 操作按钮 → 时间线（进度节点与单张注解交错）→ 冲洗记录 → 照片
- 检索：按编号 / 前缀 / 型号 / 状态 / 机身 / 时间区间 / 关键词

### 5.8 统计与运维

- 统计：月度卷数与张数、型号分布、机身使用频次、单卷周期、采购成本
- 备份：SQLite 单文件 + 附件目录打包导出

## 6. 明确不做

| 不做 | 原因 |
|---|---|
| 逐张强制记录 / 自动快门联动 | 用户明确不需要 |
| 离线同步引擎（IndexedDB outbox、冲突合并） | 可接受断网、事后补录 |
| 分享链接、只读公开页 | 需要分享时截图即可 |
| 多用户、权限体系 | 只有一个人用 |
| 库存商业管理（进销存、供应商） | 超出范围 |
| 原生 App | 网页可覆盖三端；鸿蒙 NEXT 装不了安卓 APK，Web 反而是唯一零成本形态 |

## 7. 已确认的默认约定

1. ISO 例外码使用**小写字母**
2. 序号超过 999 **自动升 4 位**（`KG2T1000`），不报错
3. 批量建档默认**整盒同型号**，暂不支持混装盒
4. 保留冲洗 / 扫描 / 归档环节，但全部可跳过
5. 进度快照允许编辑和删除，不做审计留痕
6. 详情页按「手机截图好看」设计

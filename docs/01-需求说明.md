# 胶片管理网站 — 需求说明

> 版本：v1.1（定稿）
> 最后更新：2026-11-07

## 1. 项目定位

一个**单用户私用**的胶片（胶卷）管理网站，部署在自己的服务器上，用于记录和查询胶卷从购入到拍摄完成的完整信息。

不是社区产品，不是库存商业管理软件，**不做分享功能**——需要分享时用户自己截图即可。

## 2. 用户与设备

| 项 | 说明 |
|---|---|
| 用户 | 只有一个人（本人） |
| 主力设备 | 安卓手机、鸿蒙手机、苹果手机、折叠屏 |
| 次要设备 | 电脑（偶尔） |
| 部署 | 自有服务器，通过 HTTPS 访问 |

## 3. 核心使用场景

### 3.1 拍摄前：建档

用户买了胶卷（通常**一盒多卷**），需要把每一卷录入系统。

- 胶卷外包装有**商品条形码**（EAN/UPC），可据此获得胶卷型号等基础信息
- 每卷胶卷上贴有用户自己打印的**唯一编号条码**（二维码或一维码），如 `KG2T001`
- 录入方式优先级：**扫码 > 手动输入**
- 一盒多卷时，扫或输入**第一卷**之后即可**批量建档**多卷——除编号递增外没有任何差异

### 3.2 拍摄中：记录进度

**这是最高频的操作，必须极快。**

- 用户**不做逐张记录**，绝大多数时候只记录「当前拍到第几张了」
- 支持**回填过去某个时间点**的进度（事后补录），不要求实时
- **偶尔**记录某一张的某些信息（如光圈、快门、备注），属于锦上添花，不做强制
- 可以接受网络中断，事后补录即可

### 3.3 拍摄后：查看

- 快速查看某一卷的基础信息、当前进度、历史记录
- 页面设计需**适合手机截图**：留白足、字号大、不依赖悬停交互

## 4. 术语与数据分层

系统中有三个层级，**必须严格区分**，否则数据会互相污染：

| 层级 | 中文名 | 说明 | 数量级 |
|---|---|---|---|
| 型号 | **胶卷型号库**（型录） | 一种胶片型号，如「Kodak Gold 200 135」 | 百余条 |
| 批次 | 盒 | 一次采购的一盒，如「一盒 5 卷 Gold 200」 | 几十 |
| 个体 | **胶卷库** | 真正的一卷胶卷，编号 `KG2T003` | 累计几百卷 |

> 用户原话：「胶卷型号库记录了型号信息，胶卷库则记录了每一个真正的胶卷信息。」

## 5. 胶卷编号体系（系统的地基）

### 5.1 编码结构

**编码总长度固定为 7 个字符**，这是标签纸尺寸决定的硬约束。

```
K   G   2   T   001
│   │   │   │   └── 序号：固定 3 位，首位可为 0-9 / A-Z / a-z，后两位为数字
│   │   │   └────── 画幅：T=135  M=120  D=220  S=页片  P=110  X=其他
│   │   └────────── 感光度码：见 5.2
│   └────────────── 系列：品牌内唯一，1 个字母
└────────────────── 品牌：K=Kodak  F=Fujifilm  I=Ilford  A=Agfa  L=Lomography  C=CineStill …

└──────────────────── 前缀（前 4 位）= 型号唯一键
```

**前 4 位（品牌 + 系列 + 感光度 + 画幅）唯一确定一个型号**，在系统中作为唯一索引。拿到一个编号即可反向确定是哪款胶卷。

### 5.2 感光度编码规则

规则：`v = ISO / 100`，`1–9` 用数字，`10–35` 用 `A–Z` 顺延。

| ISO | 码 | ISO | 码 | ISO | 码 |
|---|---|---|---|---|---|
| 100 | `1` | 800 | `8` | 1600 | `G` |
| 200 | `2` | 900 | `9` | 3200 | `W` |
| 400 | `4` | 1000 | `A` | 3500 | `Z` |

**例外码（小写字母，与主规则大小写区分，不冲突）：**

| ISO | 例外码 | ISO | 例外码 |
|---|---|---|---|
| 25 | `a` | 160 | `d` |
| 50 | `b` | 320 | `e` |
| 64 | `c` | 125 | `f` |
| 80 | `g` | 250 | `h` |

示例：`KPdT` = Portra 160 135；`KFfT` = Fuji 125 135；`IPbT` = Ilford Pan F Plus 50 135。

### 5.3 三位序号的约束与容量

| 约束 | 说明 |
|---|---|
| **位宽固定** | 序号永远是 3 个字符，不允许出现第 4 位 |
| **首位字符集** | `0-9` → `A-Z` → `a-z`（62 个值，按此顺序递增） |
| **后两位** | 恒为数字 `00-99` |
| **不用 `000`** | `000` 保留，不作为合法编号 |

**序号的完整序列**（同一前缀内）：

```
001 … 009 … 099 … 999
A00 … A99
B00 … B99
      ⋮
Z00 … Z99
a00 … a99
      ⋮
z00 … z99
```

**单前缀容量 = 62 × 100 − 1 = 6199 卷。**

> 个人用户单个型号累计 6199 卷基本不可能触及。真正的溢出出口仍然是「给同一型号换一个 4 位前缀」，但那只是兜底，不必担心。

**排序与比较**：序号不再是纯数字，直接按字符串比较会出错（`"A00" < "999"` 在字典序下成立，但业务上 `A00` 应排在 `999` 之后）。实现上为每卷冗余存一个可排序的整数 `seq`：

```
seq = 首位字符位次 × 100 + 后两位数字

位次：'0'-'9' → 0-9，'A'-'Z' → 10-35，'a'-'z' → 36-61
```

| 序号 | seq | 序号 | seq | 序号 | seq |
|---|---|---|---|---|---|
| `001` | 1 | `999` | 999 | `A00` | 1000 |
| `A99` | 1099 | `Z99` | 3599 | `z99` | 6199 |

所有「最大值」「下一个可用号」「排序」都以 `seq` 为准，展示时再还原成 3 字符文本。

### 5.4 解析与分流

```
K G 2 T 001
└─┬─┘ └┬┘
 前缀   序号
  │      └── 查 roll 表 → 已存在 / 新建
  └── 查 stock_prefix 表 → 型号
```

| 输入形态 | 判定 | 动作 |
|---|---|---|
| 7 位，前缀已知 | 胶卷编号 | 查 `roll`，存在则进详情，否则引导建档 |
| 7 位，前缀未知 | 未知型号 | 暂存为「待认领」，不阻塞建档 |
| 8–14 位纯数字（EAN/UPC） | 包装盒条码 | 查型号 → 预填建档 |
| 其它 | 无法识别 | 转手动输入 |

## 6. 胶卷型号库（型录）

用户的核心诉求：**随时能查「哪个编码对应哪款胶片」**。

### 6.1 职责

- 维护所有型号的客观信息与编码映射关系
- 作为建档时的型号数据来源
- 提供速查与打印

### 6.2 信息分层

一张表，字段分两组。导入时只覆盖客观层，个人层永不覆盖。

| 组 | 字段 |
|---|---|
| **客观层**（可导入/覆盖） | 前缀、品牌、系列、名称、ISO、画幅、标称张数、工艺、色彩类型、在产状态、条码、官方描述 |
| **个人层**（只有本人能填） | 昵称、常用 EI、推拉倾向、我的评价、注意事项、参考采购价 |

### 6.3 「字母占用表」（核心视图）

由于前缀固定 4 位、系列字母在品牌内唯一，**字母是稀缺资源**。型号库页必须直观展示占用情况：

```
Kodak
  A  —        B  —        C  ColorPlus     D  —
  E  Ektar    F  —        G  Gold          H  —
  I  Pro Image J —        K  —             L  —
  M  T-Max    N  —        O  —             P  Portra
  T  Tri-X    U  Ultramax V  Vision3       X  Ektachrome
  Y  —        Z  —

Fujifilm
  A  Astia    C  C200     D  Pro 160C      E  Neopan
  F  —        H  Pro 400H J  Fujicolor     N  Pro 160NS
  O  Acros    P  Premium  R  Provia        S  Superia
  T  Natura   V  Velvia   Y  Velvia 100F
```

- 已占用的字母显示对应型号，点击可进型号详情
- 空闲字母灰色显示，一眼看出还能用什么
- 满 999 的型号额外标出「需分配溢出前缀」

### 6.4 录入路径（三种，全部支持）

| 方式 | 场景 | 说明 |
|---|---|---|
| 扫包装条码 | 手头有盒子 | 扫 → 查本地条码表 → 命中即填充；未命中暂存待认领 |
| 手动填写 | 无条码 / 分装卷 | 选品牌、系列、ISO、画幅，**前缀由系统自动拼装**，不让人手输 4 位 |
| 文本批量导入 | 一次补一批 | 粘贴「Kodak Portra 400 135 36张 C-41 彩负」，系统解析并给出前缀建议，确认即入库 |

**不联网**：不接外部条码查询服务。条码由用户扫包装后本地绑定。

### 6.5 预置数据

首版按已知知识预置常见型号（约 140 条，覆盖 Kodak、Fujifilm、Ilford、Agfa、Lomography、CineStill、Foma、Rollei、ORWO 等 14 个品牌）。数据见 `data/film-stocks.tsv`。

- 条码字段留空，待用户扫包装后绑定
- 停产型号保留，标注 `discontinued`，避免历史胶卷查不到

## 7. 功能清单

### 7.1 胶卷型号库

- 型号列表、按品牌分组、按画幅/工艺/ISO 筛选
- 搜索：名称、前缀、ISO、条码
- 字母占用表
- 型号卡片上显示：已有卷数、在拍卷数、**下一个可用编号**、快捷「新建一卷 / 批量」
- 新建 / 编辑 / 删除；前缀由系统拼装并做冲突校验
- 条码绑定（一个型号可绑多个条码）
- CSV 导入导出；文本批量导入

### 7.2 胶卷库（建档）

- 扫码 / 手输编号 → 自动识别型号
- 单卷建档 / **批量建档**（一盒多卷，编号递增）
- 批量建档时做冲突检测：跳过插空 或 顺延到最大号之后
- 编号分配跨过 `999` 后自动进入 `A00`，界面正常展示，无需额外提示
- 可选记录：购入日期、单价、来源、储存位置、有效期
- **编号标签打印**
- 未识别型号的卷「暂存待认领」，事后再完善

### 7.3 编号标签打印 —— **不在本系统内实现**

> 2026-11-07 用户确认：标签用其他 app 单独打印，本站不做标签生成与打印页。

本系统只负责**产生正确的编号**，并把编号交给用户。标签的条码生成、版式排版、打印机设置都在站外完成。

| 项 | 要求 |
|---|---|
| 系统内保留 | 建档成功后展示本次生成的编号列表，支持一键复制（一行一个） |
| 系统内不做 | 条码图生成、标签模板、打印预览、`window.print()` |
| 站外打印要求 | Code 128；编码固定 7 字符，大小写须原样保留（`KG2Ta07` 的小写 `a` 有语义） |

**为什么记录 Code 128 的实测结论**：站外打印时同样要保证编码不被改写。Code Set B 含小写字母，`KG2Ta07` 可正常编码、打印、扫描，宽度与全数字编码一致。若用其他码制（如 Code 39 大写模式）或打印软件做了大小写归一化，小写序号会失去语义。

### 7.4 拍摄进度记录（核心）

- **记一笔**：记录「拍到了第几张」，2 秒完成
- 默认时间 = 现在，可选**回填过去的时间**
- 快捷增量：`+1 +2 +5 +10`，也可直接输入目标张数
- 可选附带：机身、镜头、备注
- 当前进度 = 所有进度快照中的最大值
- 进度快照可编辑、可删除

### 7.5 单张注解（辅助，非核心）

- 针对某一具体张号记录：光圈、快门、EI、曝光补偿、镜头、地点、备注、配图
- **所有字段均可空**，允许只写一句备注
- 与进度记录完全解耦

### 7.6 状态流转

```
未拆封 unopened → 已装机 loaded → 部分使用 partial → 已拍完 exposed
                                                    ↓
                            已冲洗 developed → 已扫描/归档 archived
另有：作废 void / 丢失 lost
```

冲洗、扫描、归档环节**可全部跳过，不阻塞拍摄记录**。

### 7.7 相机与镜头库

- 机身：品牌、型号、卡口、备注
- 镜头：品牌、型号、卡口、焦段、最大光圈、备注
- 初始预置：`Canon EOS 30V`、`Canon EF 50mm F1.8`

### 7.8 详情与检索

- 单卷详情：编号 → 型号卡 → 进度条 → 操作按钮 → 时间线（进度节点与单张注解交错）→ 冲洗记录 → 照片
- 检索：按编号 / 前缀 / 型号 / 状态 / 机身 / 时间区间 / 关键词

### 7.9 统计与运维

- 统计：月度卷数与张数、型号分布、机身使用频次、单卷周期、采购成本
- 备份：SQLite 单文件 + 附件目录打包导出

## 8. 明确不做

| 不做 | 原因 |
|---|---|
| 逐张强制记录 / 自动快门联动 | 用户明确不需要 |
| 离线同步引擎（IndexedDB outbox、冲突合并） | 可接受断网、事后补录 |
| 分享链接、只读公开页 | 需要分享时截图即可 |
| 多用户、权限体系 | 只有一个人用 |
| 库存商业管理（进销存、供应商） | 超出范围 |
| 原生 App | 网页可覆盖三端；鸿蒙 NEXT 装不了安卓 APK，Web 反而是唯一零成本形态 |
| 外部条码查询服务 | 国内命中率低、需 key、离线不可用 |

## 9. 已确认的默认约定

1. ISO 例外码使用**小写字母**
2. **编码固定 7 字符**：前缀 4 位 + 序号 3 位，永不变长
3. **前缀不升位**：系列字母被占用就换一个字母，不使用 5 位前缀
4. **序号首位可为字母**：`001–999` → `A00–Z99` → `a00–z99`，单前缀容量 6199 卷，足够用
5. 批量建档默认**整盒同型号**，暂不支持混装盒；单次上限 50 卷
6. 保留冲洗 / 扫描 / 归档环节，但全部可跳过
7. 进度快照允许编辑和删除，不做审计留痕
8. 详情页按「手机截图好看」设计
9. 型号库**不联网**，条码本地绑定

## 10. 待补充

> 后续用户补充的需求记录在此处。

### 10.1 扫码不做独立入口（待调整）

当前把「扫码」做成了底部导航的独立 tab，体验上很怪。**扫码应当作为「编码信息输入」的辅助手段**——即编号输入框旁边的一个小按钮，点开即扫，扫到结果回填输入框，而不是一个需要单独进入的页面。

影响范围：

| 位置 | 调整 |
|---|---|
| 底部导航 | 去掉「扫码」tab，换成「建档」（高频动作） |
| 建档页 | 编号输入框右侧加扫码按钮，弹出取景框，识别后回填 |
| 胶卷库 / 首页 | 顶部搜索框旁可加扫码按钮，扫到已有卷直接跳详情 |

优先级：M2 建档体验时一并处理，不在 M1 动。


### 10.2 在拍页快速录入（2026-11-07 用户补充）

在拍页顶部直接完成一次记录，不必先进详情页：

1. 输入或扫码填入 7 位编号 → 自动读出已建档胶卷（型号、当前张数、状态）；未建档则引导去建档
2. 选择动作：**装机**（未拆封的卷默认选中）或 **拍到第几张**
3. 时间默认当前，可改
4. 自动读取 GPS，解析出详细地址供选择（主地址 + 附近 POI），地址可编辑、可清除
5. 可选机身、镜头、备注

| 约定 | 说明 |
|---|---|
| 装机 | 落一条 `event=load` 的进度记录，胶卷状态 → 已装机，记录装机时间与机身镜头 |
| 拍满 | 张数达到总张数时自动标记「已拍完」 |
| 已拍完 / 已冲洗等 | 不能再装机或记张数 |
| 地址服务 | 高德 Web 服务 API，由服务端代理调用，key 不下发浏览器。未配置 key 时只记坐标，地址手填 |
| 隐私 | 每次解析地址会把坐标发给高德；不解析时位置不出站 |
| 坐标系 | 库内存 WGS-84 原值，调用高德前转 GCJ-02 |

### 10.3 型号收藏（2026-11-07 用户补充）

| 项 | 约定 |
|---|---|
| 收藏入口 | 型号库列表每个型号左侧星标；型号详情页顶部按钮 |
| 自动收藏 | **每次建档都会把该型号加进收藏**，单卷与批量建档一致 |
| 收藏语义 | 收藏时间戳（`favorited_at`）即「最近使用」；重复收藏刷新时间，用于排序 |
| 建档页 | 型号下拉分两组：`★ 收藏`（按收藏时间倒序）在前，`全部型号` 在后，收藏项也保留在完整列表里 |
| 手动取消 | 星标再点一次即取消；之后若无新建档，该型号不再出现在收藏组 |
| 首页扫码未建档 | 前缀已知 → 面板上直接「建档并继续」，建完即进入装机/记张数，并已收藏该型号；前缀未知 → 引导去型号库补型号 |

> 设计取舍：用时间戳而不是布尔值，是为了让收藏列表按「最近用过的」排序，而不是按点星的先后。
> 收藏属于个人层，型号库导入时不会被覆盖。

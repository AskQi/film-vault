# 胶片管理网站 — 技术方案

> 版本：v1.1（定稿）
> 最后更新：2026-11-07

## 1. 设计约束

五条硬性约束决定了整个架构：

| 约束 | 影响 |
|---|---|
| 主力设备是手机（安卓/鸿蒙/iOS/折叠屏），偶尔电脑 | 移动优先，单页大卡片布局，不做原生 App |
| 浏览器调用摄像头扫码要求**安全上下文** | 公网部署**必须 HTTPS**，`http://IP:端口` 无法扫码 |
| 部署到自有服务器 | Docker 化交付，一条命令启动 |
| 单用户、数据量小（几百卷量级） | SQLite 足够，无需 PostgreSQL；无需微服务 |
| **编码长度固定 7 字符**（标签纸尺寸限制） | 序号固定 3 位、前缀固定 4 位；标签版式恒定；单前缀容量 6199 卷 |

## 2. 总体架构

```
┌──────────────┐      HTTPS       ┌────────────────────────┐
│  手机 / 电脑  │ ───────────────▶ │  Caddy（自动 HTTPS）    │
└──────────────┘                  ├────────────────────────┤
                                  │  Node 22 + Fastify     │
                                  │  · REST API /api/*     │
                                  │  · Vue 3 PWA 静态页     │
                                  ├────────────────────────┤
                                  │  SQLite (WAL)          │
                                  │  uploads/ 附件目录      │
                                  └────────────────────────┘
```

单进程同时提供 API 与静态页面，前面挂 Caddy 处理证书。SQLite 与附件目录挂载为 Docker 数据卷。

## 3. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 前端框架 | Vue 3 + TypeScript + Vite | 与现有 RuoYi-Vue 技术栈一致，维护成本低 |
| 状态管理 | Pinia | 轻量，够用 |
| 样式 | Tailwind CSS | 断点驱动，折叠屏/手机/桌面一套代码 |
| PWA | vite-plugin-pwa | 加到主屏幕后全屏体验 |
| 扫码 | `BarcodeDetector` API + `barcode-detector` WASM polyfill | 安卓 Chrome 原生支持；iOS Safari / 鸿蒙走 WASM 兜底，**无任何原生依赖** |
| 一维码生成 | ~~`bwip-js`~~ | **已移除**：标签改为站外打印，本站只输出编号文本。Code 128 Code Set B 含小写、`KG2Ta07` 等宽可扫的结论仍然成立，供站外 app 参考 |
| 二维码生成 | `qrcode` | 备选方案 |
| 后端 | Node 22 LTS + Fastify | 同语言、性能足够、生态成熟 |
| 参数校验 | Zod | 前后端共享 schema 与类型 |
| ORM | Drizzle ORM + `better-sqlite3` | 类型安全、迁移可版本化、全平台预编译二进制 |
| 数据库 | SQLite（WAL 模式） | 单用户最优解；备份 = 复制文件 |
| 鉴权 | 单用户 PIN → HttpOnly Cookie 长效会话 | 公网部署的最低门槛 |
| 测试 | Vitest | 重点覆盖编号解析与批量生成 |
| 部署 | Docker Compose（app + caddy） | 服务器一条命令启动 |
| 包管理 | pnpm workspace | monorepo 管理 |

## 4. 数据模型

### 4.1 码表

```sql
brand(code TEXT PRIMARY KEY, name TEXT, sort INT);
film_series(id INTEGER PRIMARY KEY, brand_code TEXT, code TEXT, name TEXT,
            UNIQUE(brand_code, code));
iso_code_map(code TEXT PRIMARY KEY, iso INT, is_exception INT DEFAULT 0);
format_code_map(code TEXT PRIMARY KEY, name TEXT, sort INT);  -- T/M/D/S/P/X
```

### 4.2 胶卷型号库

```sql
film_stock(
  id INTEGER PRIMARY KEY,
  -- 客观层（导入可覆盖）
  brand_code   TEXT NOT NULL,
  series_code  TEXT NOT NULL,
  iso_code     TEXT NOT NULL,
  iso          INT  NOT NULL,
  format_code  TEXT NOT NULL,      -- T/M/D/S/P/X
  format       TEXT NOT NULL,      -- 135/120/220/4x5...
  name         TEXT NOT NULL,      -- 'Kodak Gold 200 135'
  nominal_frames INT,              -- 135 为 24/36；120 按片盒决定时可空
  default_frames INT,              -- 建档时的默认张数（120 按片盒规格）
  process      TEXT,               -- C-41 / E-6 / BW / ECN-2
  color_type   TEXT,               -- color_negative / color_positive / bw
  status       TEXT DEFAULT 'active',   -- active / discontinued / cinema
  description  TEXT,
  -- 个人层（导入永不覆盖）
  nickname     TEXT,
  usual_ei     INT,
  push_pull_pref TEXT,             -- 如 '+1'
  my_rating    INT,                -- 1-5
  my_notes     TEXT,               -- '阴天偏黄，+1/3 档'
  ref_price    NUMERIC,
  -- 元数据
  created_at TEXT, updated_at TEXT, deleted_at TEXT
);
CREATE UNIQUE INDEX ux_stock_name ON film_stock(brand_code, series_code, iso_code, format_code);
```

> 客观层与个人层**放在同一张表的两组字段**里。两者严格 1:1，拆表只会多一次 JOIN 和一处不一致的可能；导入时按 `prefix` 只写客观层列即可。

### 4.3 前缀映射（支持一个型号绑多个前缀）

```sql
stock_prefix(
  prefix     TEXT PRIMARY KEY,     -- 4 位，如 'KG2T'
  stock_id   INT NOT NULL,
  is_primary INT DEFAULT 1,        -- 1=主前缀，0=备用前缀（极少用到）
  seq_max    INT NOT NULL DEFAULT 0,   -- 该前缀已分配到的最大序号（可排序整数），用于「下一个可用编号」
  note       TEXT
);
CREATE UNIQUE INDEX ux_prefix_primary ON stock_prefix(stock_id) WHERE is_primary = 1;
```

**为什么单独成表**：前缀与型号是多对一，方便将来极端情况下给同一型号挂第二个前缀。但正常使用中单前缀容量已达 6199 卷，用不上。

`seq_max` 而非 `MAX(seq)` 实时聚合：避免删除卷后编号被回收重用，也方便批量分配时一次预留 N 个。

### 4.4 条码绑定

```sql
stock_barcode(barcode TEXT PRIMARY KEY, stock_id INT NOT NULL, source TEXT, created_at TEXT);
```

一个型号可绑多个条码（不同地区、不同批次包装）。条码**不来自联网查询**，由用户扫包装后本地绑定。

### 4.5 机身镜头

```sql
camera(id, brand, model, mount, notes);
lens(id, brand, model, mount, focal_mm, max_aperture, notes);
```

### 4.6 盒与卷

```sql
box(id, stock_id, label, purchased_at, unit_price, source, storage, notes, created_at);

roll(
  id INTEGER PRIMARY KEY,
  code       TEXT UNIQUE NOT NULL,   -- 'KG2T004'，固定 7 字符
  prefix     TEXT NOT NULL,          -- 冗余存，便于按前缀检索
  serial_txt TEXT NOT NULL,          -- 3 字符序号原样：'004' / 'A07' / 'z12'
  seq        INT  NOT NULL,          -- 可排序整数：'004'=4, 'A07'=1007, 'z12'=6112
  stock_id   INT  NOT NULL,
  box_id     INT,
  frames_total INT NOT NULL,
  status     TEXT NOT NULL DEFAULT 'unopened',
  camera_id  INT, lens_id INT,
  ei INT, push_pull INT DEFAULT 0,
  loaded_at TEXT, finished_at TEXT, expiry_date TEXT,
  notes TEXT, created_at TEXT, updated_at TEXT, deleted_at TEXT,
  CHECK (seq BETWEEN 1 AND 6199),
  CHECK (length(code) = 7)
);
CREATE INDEX idx_roll_status ON roll(status, updated_at DESC);
CREATE UNIQUE INDEX ux_roll_prefix_seq ON roll(prefix, seq);
```

**为什么同时存 `serial_txt` 和 `seq`**：序号首位可以是字母（`001–999` → `A00–Z99` → `a00–z99`），字符串排序会错（`'A00' < '999'` 成立但业务上更大）。因此：

- `serial_txt` 用于**展示和拼编码**
- `seq` 用于**排序、取最大值、找下一个可用号、唯一约束**

换算规则 `seq = 首位位次 × 100 + 后两位`，位次：`'0'-'9'`→0-9，`'A'-'Z'`→10-35，`'a'-'z'`→36-61。

**注意：不冗余存 `frames_shot`。** 当前进度由 `MAX(roll_progress.reached_frame)` 推导，避免「同步维护 + 删记录时重算」的一致性隐患。几百卷的数据量下聚合查询无压力。

### 4.7 进度快照（核心表）

```sql
frame_note(
```

**所有业务字段均可空**，与 `roll_progress` 完全解耦。

### 4.9 待认领型号

```sql
pending_stock(
```

扫到未知前缀时不打断建档，先落这张表；之后在型号库页消化。

## 6. 编号解析模块（独立可测）

```ts
// 固定 7 字符：4 位前缀 + 3 位序号
// 前缀第 3 位允许小写（ISO 例外码 d/f/g/h…），所以不加 i 标志
// 序号：首位 0-9/A-Z/a-z，后两位恒为数字
const ROLL_RE = /^([A-Z][A-Z][0-9A-Za-z][A-Z])([0-9A-Za-z]\d{2})$/;

/** 序号首位 → 位次：'0'-'9'→0-9，'A'-'Z'→10-35，'a'-'z'→36-61 */
function headIndex(ch: string): number {
  if (ch >= '0' && ch <= '9') return ch.charCodeAt(0) - 48;         // 0-9
  if (ch >= 'A' && ch <= 'Z') return ch.charCodeAt(0) - 65 + 10;    // 10-35
  if (ch >= 'a' && ch <= 'z') return ch.charCodeAt(0) - 97 + 36;    // 36-61
  return -1;
}

/** 3 字符序号 → 可排序整数 1..6199 */
export function seqFromSerial(s: string): number {
  const h = headIndex(s[0]);
  const tail = Number(s.slice(1));
  if (h < 0 || Number.isNaN(tail)) throw new Error(`非法序号 ${s}`);
  return h * 100 + tail;
}

/** 可排序整数 → 3 字符序号 */
export function serialFromSeq(seq: number): string {
  const h = Math.floor(seq / 100), tail = seq % 100;
  const head = h < 10 ? String(h)
             : h < 36 ? String.fromCharCode(65 + h - 10)
             : String.fromCharCode(97 + h - 36);
  return head + String(tail).padStart(2, '0');
}

export function parseRollCode(raw: string): ParseResult {
  const s = raw.trim().replace(/[\s\-]/g, '');
  const m = ROLL_RE.exec(s);
  if (!m) return { kind: 'invalid', raw };

  const [, prefix, serialTxt] = m;
  const seq = seqFromSerial(serialTxt);
  if (seq < 1) return { kind: 'invalid', raw };      // '000' 保留

  const stockId = db.stockByPrefix(prefix);
  if (!stockId) return { kind: 'unknown_prefix', prefix, seq };

  return { kind: 'roll', prefix, seq, serialTxt, stock: stockId, code: prefix + serialTxt };
}
```

**大小写处理原则**：

| 位置 | 大小写规则 |
|---|---|
| 品牌位（1） | 必须大写 |
| 系列位（2） | 必须大写 |
| **ISO 位（3）** | **保留原样**——小写是例外码的语义，`d`≠`D` |
| 画幅位（4） | 必须大写 |
| **序号首位（5）** | **保留原样**——`A` 与 `a` 是不同序号（相差 2600 卷） |
| 序号后两位（6–7） | 纯数字 |

因此**全局 `toUpperCase()` / `toLowerCase()` 都是错的**：
- `KPdT`（Portra 160）会被改成 `KPDT`（不存在）
- `KG2TA07` 会被改成 `KG2Ta07`（序号 1007 变成 3607）

录入框应关闭自动大写，扫码输入时不做裁剪。**注意与「条码本身」区分**：Code 128 是无损编码，扫码结果原样保留即可。

扫码分流规则：

| 输入形态 | 判定 | 动作 |
|---|---|---|
| 7 位，前缀已知 | 胶卷编号 | 查 `roll`，存在则进详情，否则引导建档 |
| 7 位，前缀未知 | 未知型号 | 写入 `pending_stock`，仍允许建档 |
| 8–14 位纯数字（EAN/UPC） | 包装盒条码 | 查 `stock_barcode` → 预填建档 |
| 其它 | 无法识别 | 转手动输入 |

## 7. 编号交接（标签站外打印）

### 7.1 版式

**标签不在本系统内生成**（2026-11-07 用户确认）：条码图、版式、打印机设置都在站外 app 完成。本系统只负责给出正确的编号。

### 7.2 编号交接流程

```
建档完成 → 页面展示本次生成的编号列表（一行一个）→ 一键复制 → 粘贴到站外打印 app
```

复制出来的是纯文本，形如：

```
KG2T001
KG2T002
KG2T003
```

**站外打印时的约束**（写在这里是为了将来换打印工具时不忘掉）：

- 码制用 **Code 128**，Code Set B 含小写字母
- 7 个字符**原样输出，不得做大小写归一化**：`KG2Ta07` 里的小写 `a` 是序号 3607，改成 `A` 就变成 1007
- 编码长度恒定 7 → 条码宽度恒定，版式可预先固定
- 常用尺寸：`40×12mm`（热敏）、`50×15mm`、A4 不干胶 `3×8` 格
- 标签内容只有编码，不印型号与张数——保持最小尺寸，信息在系统里查

## 8. 页面与交互

| 页面 | 内容 |
|---|---|
| 首页 | 在拍胶卷卡片列表（编号、型号、进度条、操作）、底部导航 |
| 记一笔（底部抽屉） | 当前进度大字、目标张数输入、快捷增量、时间选择、折叠的更多选项 |
| 扫码 | 全屏摄像头 + 手输兜底 |

| 胶卷详情 | 编号大字 → 型号卡 → 进度条 → 操作 → 时间线 → 冲洗 → 照片 |
| **型号库** | 品牌分组列表 + **字母占用表** + 搜索 + 待认领区 |
| 型号详情 | 客观信息 + 个人笔记 + 条码列表 + 该型号所有卷 + 下一个编号 |

- 移动优先，单列大卡片；`md` 以上自动双列（兼顾折叠屏展开与桌面）
- 不依赖悬停（手机没有 hover）
- 详情页留白足、字号大，**适合直接截图分享**
- 记一笔全程 2 秒内：打开 → 敲数字 → 保存

## 10. 部署

```yaml
# docker-compose.yml 结构示意
services:
  app:
    build: .
    volumes:
      - ./storage:/app/storage    # SQLite + uploads + 备份
    environment:
      - PIN=${PIN}
      - SESSION_SECRET=${SESSION_SECRET}
  caddy:
    image: caddy:2
    ports: ["80:80", "443:443"]
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile
      - caddy_data:/data
```

**运行时数据目录是 `storage/`，不是 `data/`。** `data/` 放的是随仓库提交的型号库 seed（`film-stocks.tsv`），两者混用会导致 seed 数据被数据卷覆盖或误提交——M0 落地时即按此分开。

**HTTPS 是硬约束**：没有 HTTPS，手机浏览器不允许调用摄像头，扫码功能不可用。Caddy 自动签发证书，一条命令解决。

**会话签名密钥 `SESSION_SECRET` 必须固定**：不设置时每次重启会随机生成，导致所有设备掉登录。

备份：`storage/` 目录整体打包即可（SQLite 用 `.backup` 或先 checkpoint 再复制）。

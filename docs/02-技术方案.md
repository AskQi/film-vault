# 胶片管理网站 — 技术方案

> 版本：v1.0（定稿）
> 最后更新：2026-11-07

## 1. 设计约束

四条硬性约束决定了整个架构：

| 约束 | 影响 |
|---|---|
| 主力设备是手机（安卓/鸿蒙/iOS/折叠屏），偶尔电脑 | 移动优先，单页大卡片布局，不做原生 App |
| 浏览器调用摄像头扫码要求**安全上下文** | 公网部署**必须 HTTPS**，`http://IP:端口` 无法扫码 |
| 部署到自有服务器 | Docker 化交付，一条命令启动 |
| 单用户、数据量小（几百卷量级） | SQLite 足够，无需 PostgreSQL；无需微服务 |

## 2. 总体架构

```
┌──────────────┐      HTTPS       ┌────────────────────────┐
│  手机 / 电脑  │ ───────────────▶ │  Caddy（自动 HTTPS）    │
└──────────────┘                  ├────────────────────────┤
                                  │  Node 22 + Fastify     │
                                  │  · REST API /api/*     │
                                  │  · Vue 3 PWA 静态页     │
                                  ├────────────────────────┤
                                  │  SQLite (WAL)          │
                                  │  uploads/ 附件目录      │
                                  └────────────────────────┘
```

单进程同时提供 API 与静态页面，前面挂 Caddy 处理证书。SQLite 与附件目录挂载为 Docker 数据卷。

## 3. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 前端框架 | Vue 3 + TypeScript + Vite | 与现有 RuoYi-Vue 技术栈一致，维护成本低 |
| 状态管理 | Pinia | 轻量，够用 |
| 样式 | Tailwind CSS | 断点驱动，折叠屏/手机/桌面一套代码 |
| PWA | vite-plugin-pwa | 加到主屏幕后全屏体验，弱网可用 |
| 扫码 | `BarcodeDetector` API + `barcode-detector` WASM polyfill | 安卓 Chrome 原生支持；iOS Safari / 鸿蒙走 WASM 兜底，**无任何原生依赖** |
| 二维码生成 | `qrcode` | 标签打印用 |
| 后端 | Node 22 LTS + Fastify | 同语言、性能足够、生态成熟 |
| 参数校验 | Zod | 前后端共享 schema 与类型 |
| ORM | Drizzle ORM + `better-sqlite3` | 类型安全、迁移可版本化、全平台预编译二进制 |
| 数据库 | SQLite（WAL 模式） | 单用户最优解；备份 = 复制文件 |
| 鉴权 | 单用户 PIN → HttpOnly Cookie 长效会话 | 公网部署的最低门槛 |
| 测试 | Vitest | 重点覆盖编号解析与批量生成 |
| 部署 | Docker Compose（app + caddy） | 服务器一条命令启动 |
| 包管理 | pnpm workspace | monorepo 管理 |

## 4. 数据模型

### 4.1 码表

```sql
brand(code TEXT PRIMARY KEY, name TEXT, sort INT);
film_series(id INTEGER PRIMARY KEY, brand_code TEXT, code TEXT, name TEXT,
            UNIQUE(brand_code, code));
iso_code_map(code TEXT PRIMARY KEY, iso INT, is_exception INT DEFAULT 0);
```

### 4.2 胶卷库

```sql
film_stock(
  id INTEGER PRIMARY KEY,
  prefix      TEXT UNIQUE NOT NULL,  -- 'KG2T'
  brand_code  TEXT NOT NULL,
  series_code TEXT NOT NULL,
  iso_code    TEXT NOT NULL,
  iso         INT NOT NULL,
  format_code TEXT NOT NULL,          -- 'T' / 'M' / ...
  format      TEXT NOT NULL,          -- '135' / '120'
  name        TEXT NOT NULL,          -- 'Kodak Gold 200 135'
  nominal_frames INT NOT NULL DEFAULT 36,
  default_ei  INT,
  process     TEXT,                   -- C-41 / E-6 / BW
  color_type  TEXT,                   -- color_negative / color_positive / bw
  notes       TEXT
);

stock_barcode(barcode TEXT PRIMARY KEY, stock_id INT NOT NULL, source TEXT);
```

### 4.3 机身镜头

```sql
camera(id, brand, model, mount, notes);
lens(id, brand, model, mount, focal_mm, max_aperture, notes);
```

### 4.4 盒与卷

```sql
box(id, stock_id, label, purchased_at, unit_price, source, storage, notes, created_at);

roll(
  id INTEGER PRIMARY KEY,
  code       TEXT UNIQUE NOT NULL,   -- 'KG2T004'
  stock_id   INT NOT NULL,
  box_id     INT,
  serial     INT NOT NULL,
  frames_total INT NOT NULL,
  status     TEXT NOT NULL DEFAULT 'unopened',
  camera_id  INT, lens_id INT,
  ei INT, push_pull INT DEFAULT 0,
  loaded_at TEXT, finished_at TEXT, expiry_date TEXT,
  notes TEXT, created_at TEXT, updated_at TEXT, deleted_at TEXT
);
CREATE INDEX idx_roll_status ON roll(status, updated_at DESC);
```

**注意：不冗余存 `frames_shot`。** 当前进度由 `MAX(roll_progress.reached_frame)` 推导，避免「同步维护 + 删记录时重算」的一致性隐患。几百卷的数据量下聚合查询无压力。

### 4.5 进度快照（核心表）

```sql
roll_progress(
  id INTEGER PRIMARY KEY,
  roll_id INT NOT NULL,
  reached_frame INT NOT NULL,     -- 拍到了第几张
  happened_at   TEXT NOT NULL,    -- 什么时候拍的（可回填过去时间）
  camera_id INT, lens_id INT,     -- 可选
  note TEXT,
  created_at TEXT
);
CREATE INDEX idx_progress_roll ON roll_progress(roll_id, happened_at DESC);
```

### 4.6 单张注解（辅助）

```sql
frame_note(
  id INTEGER PRIMARY KEY,
  roll_id INT NOT NULL,
  frame_no INT NOT NULL,
  aperture TEXT, shutter TEXT, ei INT, ev_offset TEXT,
  lens_id INT, location TEXT,
  note TEXT, photo_path TEXT,
  happened_at TEXT, created_at TEXT
);
```

**所有业务字段均可空**，与 `roll_progress` 完全解耦。

### 4.7 冲洗与附件

```sql
development(id, roll_id, method, process, developer, dilution, temp_c,
            duration_sec, agitation, push_pull, lab_name, dev_at,
            rating, issues, notes);

asset(id, roll_id, kind, path, thumb_path, mime, size, created_at);
```

### 4.8 ER 关系

```
brand ─┬─ film_series           box ─┐
       └─ iso_code_map              ├─ roll ─┬─ roll_progress
film_stock ── stock_barcode          │        ├─ frame_note
    │                               │        ├─ development
    └───────────────────────────────┘        └─ asset
camera ─┬─ roll (使用)
        └─ roll_progress
lens  ──┬─ roll
        ├─ roll_progress
        └─ frame_note
```

## 5. 接口设计

```

# 建档

# 卷

PATCH  /api/rolls/:id

# 进度（核心）
GET    /api/rolls/:id/progress

# 单张注解
POST   /api/rolls/:id/frame-notes

# 冲洗 / 其他

```

## 6. 编号解析模块（独立可测）

```ts
// prefix = 品牌1 + 系列1 + ISO码1 + 画幅1；序号 = 其后全部数字
const ROLL_RE = /^([A-Z]{2})([0-9A-Za-z])([A-Z])(\d{3,5})$/;

export function parseRollCode(raw: string): ParseResult {
  const s = raw.trim().toUpperCase().replace(/\s/g, '');
  const m = ROLL_RE.exec(s);
  if (!m) return { kind: 'invalid' };

  const prefix = m[1] + m[2] + m[3];
  const serial = parseInt(m[4], 10);
  const stock  = db.stockByPrefix(prefix);

  if (!stock) return { kind: 'unknown_prefix', prefix, serial };
  return { kind: 'roll', prefix, serial, stock, code: prefix + m[4] };
}
```

扫码分流规则：

| 输入形态 | 判定 | 动作 |
|---|---|---|
| `KG2T004`，前缀已知 | 胶卷编号 | 进详情 / 提示已存在 |
| `KG2T004`，前缀未知 | 新型号 | 引导建档并绑定前缀 |
| 8–14 位纯数字（EAN/UPC） | 包装盒条码 | 查出型号 → 预填建档 |
| 其它 | 无法识别 | 转手动输入 |

## 7. 页面与交互

| 页面 | 内容 |
|---|---|
| 首页 | 在拍胶卷卡片列表（编号、型号、进度条、操作按钮）、底部导航 |
| 记一笔（底部抽屉） | 当前进度大字、目标张数输入、快捷增量、时间选择（现在/回填）、折叠的更多选项 |
| 扫码 | 全屏摄像头 + 手输兜底 |
| 建档 | 扫码/手输 → 自动识别型号 → 单卷或批量（数量 + 冲突预览） |
| 胶卷详情 | 编号大字 → 型号卡 → 进度条 → 操作 → 时间线 → 冲洗 → 照片 |
| 胶卷库 | 型号列表、条码绑定、CSV 导入导出 |
| 相机镜头 | CRUD |
| 统计 | 月度、型号分布、机身使用频次、成本 |

**设计要点**

- 移动优先，单列大卡片；`md` 以上自动双列（兼顾折叠屏展开与桌面）
- 不依赖悬停（手机没有 hover）
- 详情页留白足、字号大，**适合直接截图分享**
- 记一笔全程 2 秒内：打开 → 敲数字 → 保存

## 8. 三端兼容要点

| 平台 | 注意点 |
|---|---|
| iOS Safari | 不支持 `BarcodeDetector`，必须 WASM polyfill；「添加到主屏幕」获得全屏 |
| 安卓 Chrome | `BarcodeDetector` 原生支持，性能最佳 |
| 鸿蒙 NEXT | 不能装安卓 APK，网页是唯一低成本形态；扫码走 WASM |
| 折叠屏 | Tailwind 断点驱动，不写死宽度 |
| 桌面 | 同一套页面，多列布局 |

## 9. 部署

```yaml
# docker-compose.yml 结构示意
services:
  app:
    build: .
    volumes:
      - ./data:/app/data          # SQLite + uploads
    environment:
      - PIN=xxxx
  caddy:
    image: caddy:2
    ports: ["80:80", "443:443"]
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile
      - caddy_data:/data
```

**HTTPS 是硬约束**：没有 HTTPS，手机浏览器不允许调用摄像头，扫码功能不可用。Caddy 自动签发证书，一条命令解决。

备份：`data/` 目录整体打包即可（SQLite 用 `.backup` 或先 checkpoint 再复制）。

# 胶片管理网站 — 部署说明

> 最后更新：2026-11-07

## 1. 部署环境

| 项 | 值 |
|---|---|
| 域名 | `film.ddns.sharepeople.cn` |
| 应用服务器 | `root@192.168.10.42`（Ubuntu 24.04 VM），项目在 `/opt/film-vault` |
| TLS 终止 | 在 `112.64.109.232` 的上层反向代理上，域名 `:8443` 转发到本机 `3300` |
| 80 / 443 | 已对公网开放，由宿主机 nginx 占用 |
| 形态 | nginx（宿主机，负责 HTTPS 与证书）→ `127.0.0.1:3300` → app 容器 |

服务器上已经有 nginx，所以**不用 compose 里的 Caddy**（它会抢 80/443）。Caddy 留作可选 profile，默认不启动。

**为什么必须 HTTPS**：浏览器只在安全上下文（`https://` 或 `localhost`）下允许调用摄像头和定位。用 `http://` 访问时扫码和 GPS 都不可用，这是浏览器的限制，没有办法绕过。

服务器需要：Docker 20.10+（含 `docker compose` 插件）、`certbot`、`git`。

## 2. 首次部署

以下命令都在服务器上执行。涉及 `/etc/nginx` 的步骤需要 sudo。

### 2.1 拉代码、配置

```bash
git clone <仓库地址> ~/film-vault
cd ~/film-vault
cp .env.example .env
```

编辑 `.env`：

```ini
PIN=你的PIN                         # 不允许 1234，否则拒绝启动
SESSION_SECRET=<openssl rand -hex 32 的输出>   # 固定下来，否则重启后所有设备都要重新登录
AMAP_KEY=<高德 Web 服务 key>          # 可选，GPS 转地址
SITE_ADDRESS=film.ddns.sharepeople.cn   # 只有启用 Caddy profile 时用到
```

### 2.2 启动 app

```bash
docker compose up -d --build
docker compose logs -f app       # 看到 Server listening at http://0.0.0.0:3300 即可 Ctrl+C
curl -s http://127.0.0.1:3300/api/health   # 应返回 {"ok":true}
```

首次启动会自动建库，写入 139 条型号和预置的机身镜头，不需要单独跑 seed。app 只绑定了 `127.0.0.1:3300`，外网无法绕过 nginx 直接访问。

### 2.3 签证书

先放一份只有 80 端口的配置，让 certbot 能完成校验：

```bash
sudo mkdir -p /var/www/certbot
sudo cp deploy/nginx/film-vault.http-only.conf /etc/nginx/sites-available/film-vault.conf
sudo ln -sf /etc/nginx/sites-available/film-vault.conf /etc/nginx/sites-enabled/film-vault.conf
sudo nginx -t && sudo systemctl reload nginx

# 确认外网能访问到这份配置（应返回 waiting for certificate）
curl http://film.ddns.sharepeople.cn/

sudo certbot certonly --webroot -w /var/www/certbot -d film.ddns.sharepeople.cn
```

> 注意：服务器上 `sites-enabled/default` 这个默认站点会响应所有未匹配的域名（就是现在看到的 nginx 欢迎页）。它不影响本站，因为本站配置了精确的 `server_name`，可以保留不动。

### 2.4 启用 HTTPS

```bash
sudo cp deploy/nginx/film-vault.conf /etc/nginx/sites-available/film-vault.conf
sudo nginx -t && sudo systemctl reload nginx
```

`nginx -t` 报 `http2` 相关警告时：nginx 1.18 支持 `listen 443 ssl http2` 写法，可以忽略；如果直接报错，把两处 `http2` 删掉即可。

证书续期：certbot 安装时会自带定时任务。续期后需要 reload nginx，执行一次下面的命令配置好 hook：

```bash
echo -e '#!/bin/sh\nsystemctl reload nginx' | sudo tee /etc/letsencrypt/renewal-hooks/deploy/reload-nginx.sh
sudo chmod +x /etc/letsencrypt/renewal-hooks/deploy/reload-nginx.sh
sudo certbot renew --dry-run
```

### 2.5 验收

手机浏览器打开 `https://film.ddns.sharepeople.cn`，用 PIN 登录，然后检查：

1. 地址栏显示锁形图标，没有证书警告
2. 型号库有 139 条
3. 在拍页点扫码按钮，浏览器弹出摄像头授权（说明 HTTPS 生效）
4. 输入一个已建档的编号，点「读取」后会自动定位，并出现地址候选（说明 GPS 和高德 key 都生效）

### 备选：宿主机没有 nginx 时

```bash
docker compose --profile caddy up -d --build
```

Caddy 会占用 80/443 并自动签证书。此时 `.env` 里的 `SITE_ADDRESS` 必填。

## 2.6 开机自启（已配置）

两层保障，都已启用并验证：

| 层 | 作用 |
|---|---|
| `systemctl enable docker` | Docker 服务随系统启动（安装时默认已启用） |
| 容器 `restart: unless-stopped` | Docker 起来后自动拉起容器 |
| `/etc/systemd/system/film-vault.service` | 兜底：即使容器被 `docker compose down` 删掉，开机也会重新拉起 |

`film-vault.service` 内容：

```ini
[Unit]
Description=film-vault (胶片管理)
Requires=docker.service
After=docker.service network-online.target
Wants=network-online.target

[Service]
Type=oneshot
RemainAfterExit=yes
WorkingDirectory=/opt/film-vault
ExecStart=/usr/bin/docker compose up -d --remove-orphans
ExecStop=/usr/bin/docker compose stop
TimeoutStartSec=0

[Install]
WantedBy=multi-user.target
```

为什么需要第三层：`restart: unless-stopped` 只在容器**存在**时生效。一旦手动
`docker compose down`，容器被删除，那之后重启机器不会再自动起来。systemd 单元
负责把这种情况补上。

验证方式：`systemctl restart docker` 后等几秒，`docker compose ps` 应显示
`Up (healthy)`。

## 2.7 生产环境数据保护

**库里的数据是真实数据，不是测试数据。任何变更都不得破坏已有数据。**

红线：

- 禁止在生产执行删除 / 重建 / 重置数据库的操作
- 数据库迁移只允许**增量**：加表、加列（可空或带默认值）、加索引
- 禁止 `DROP TABLE` / `DROP COLUMN`
- 改字段语义时先加新字段双写，确认无回退风险后再考虑废弃旧字段
- 每次部署前先备份

备份（部署前必做）：

```bash
cd /opt/film-vault
docker compose exec -T app node -e "
  const D=require('better-sqlite3');
  new D('/app/storage/film-vault.db').pragma('wal_checkpoint(TRUNCATE)');
"
tar czf ~/backup-$(date +%F-%H%M).tar.gz storage
```

或走应用内「统计 → 备份」下载 zip。

## 3. 日常运维

### 3.1 更新

```bash
cd ~/film-vault
git pull
docker compose up -d --build
```

数据在 `storage/` 目录，重建镜像不影响数据。启动时会自动执行缺失的数据库迁移，并刷新型号库的客观层（个人层不会被覆盖）。nginx 配置一般不用动。

### 3.2 备份

两种方式，建议都做：

**应用内导出**（推荐，随时可用）

统计页点「备份」，下载 `film-vault-backup-YYYY-MM-DD.zip`。里面是 checkpoint 后的主库 + uploads + 恢复说明。

**整目录复制**（服务器侧）

```bash
# 先 checkpoint，避免复制到写了一半的 WAL
docker compose exec app node -e "
  const D=require('better-sqlite3');
  new D('/app/storage/film-vault.db').pragma('wal_checkpoint(TRUNCATE)')
"
tar czf ~/backup-$(date +%F).tar.gz -C ~/film-vault storage
```

建议加进 crontab，每天凌晨跑一次，保留最近 30 份：

```cron
17 3 * * * cd ~/film-vault && tar czf ~/backups/fv-$(date +\%F).tar.gz storage && find ~/backups -name 'fv-*.tar.gz' -mtime +30 -delete
```

### 3.3 恢复

```bash
docker compose stop app

# 用备份包里的文件覆盖
rm -f storage/film-vault.db-wal storage/film-vault.db-shm
unzip -o film-vault-backup-2026-11-07.zip film-vault.db -d storage/

docker compose start app
```

**必须删掉旧的 `-wal` 与 `-shm`**，否则 SQLite 会用旧日志覆盖恢复进来的数据。

### 3.4 查看日志

```bash
docker compose logs -f app                 # 应用日志
sudo tail -f /var/log/nginx/access.log     # 访问日志
sudo tail -f /var/log/nginx/error.log      # 反代与证书相关错误
```

## 4. 三端实测清单

部署后必须逐项过一遍，任何一项不过都会影响日常使用。

| 平台 | 检查项 | 关注点 |
|---|---|---|
| iOS Safari | 扫码建档 | Safari 无原生 `BarcodeDetector`，走 WASM polyfill，识别速度会慢一点 |
| iOS Safari | 添加到主屏幕 | 全屏运行、无地址栏，状态栏配色是否协调 |
| 安卓 Chrome | 扫码建档 | 原生 `BarcodeDetector`，应明显快于 iOS |
| 安卓 Chrome | 标签打印 | 系统打印对话框的边距与缩放设置 |
| 鸿蒙浏览器 | 扫码 | 鸿蒙 NEXT 装不了安卓 APK，网页是唯一形态；需确认 WASM 可用 |
| 折叠屏 | 展开/折叠切换 | 布局是否错乱，卡片是否被拉伸 |
| 折叠屏 | 记一笔抽屉 | 展开态下抽屉宽度是否受限 |
| 桌面 | 列表页 | `md` 以上应自动双列 |
| 全平台 | 后台切回 | 切走再回来，进度是否显示为最新 |

### 打印校准

首次打印标签前，先用一张普通纸试打，量一下：

- Code 128 条码的实际宽度（应约 30mm，取决于模板）
- 人眼可读编码的字号（应保证 30cm 距离肉眼可辨）
- 打印对话框里关掉「页眉页脚」、边距设为「无」或「最小」

校准好后记下这套设置，以后每次打印都用同一套。

## 5. 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 服务起不来，日志提示「生产环境必须设置 PIN」 | `.env` 没填 PIN 或仍是 1234 | 改 `.env` 后 `docker compose up -d` |
| 访问域名证书报错 | DNS 未生效，或 80 端口不通 | `dig film.ddns.sharepeople.cn` 确认解析到本机；确认 80 端口可达 |
| certbot 校验失败 | 请求被 default 站点接走了 | `curl http://film.ddns.sharepeople.cn/` 应返回 waiting for certificate；不对就检查 `sites-enabled/film-vault.conf` 是否生效 |
| 打开域名显示 502 | app 容器没起来 | `docker compose ps`、`curl http://127.0.0.1:3300/api/health` |
| DDNS 域名突然打不开 | 家宽公网 IP 变了，DDNS 还没更新 | `dig` 对比服务器当前公网 IP；证书不受 IP 变化影响 |
| 地址候选为空 | `AMAP_KEY` 未配置或 key 设了 IP 白名单 | 看 app 日志；在高德控制台把服务器公网 IP 加入白名单 |
| 扫码按钮提示不支持 | 用了 `http://` 访问 | 必须走 `https://` |
| 扫码提示「不支持条码识别」 | WASM polyfill 未加载 | 检查浏览器控制台是否有 CSP 或跨域报错 |
| 所有设备突然掉登录 | `SESSION_SECRET` 每次重启都变 | 在 `.env` 里固定该值 |
| 数据看起来是旧的 | 浏览器 PWA 缓存了旧页面 | 强制刷新，或在设置里清除站点数据 |
| 数据库锁死 | 多进程访问同一 SQLite | 确认只有一个 app 容器在跑 |

## 6. 架构备忘

```
浏览器 ──HTTPS──▶ nginx（宿主机，证书 by certbot）
                    └─HTTP─▶ 127.0.0.1:3300 ─▶ app 容器 (Fastify)
                                                 ├── SQLite  /app/storage/film-vault.db
                                                 ├── uploads /app/storage/uploads
                                                 └──HTTPS──▶ 高德逆地理编码（仅解析地址时）
```

- 只有一个 app 容器。SQLite 单进程写入，不要水平扩容。
- `storage/` 是唯一的持久化目录，其余都是可重建的。
- 前端静态资源打在 app 镜像里，由 Fastify 直接托管；nginx 只做 TLS 终止和反代。

# 胶片管理网站 — 部署说明

> 最后更新：2026-11-07

## 1. 前置条件

| 项 | 要求 |
|---|---|
| 服务器 | Linux（x86_64 或 arm64），1 核 1G 内存即可 |
| Docker | 20.10+，含 `docker compose` 插件 |
| 域名 | 一个能解析到服务器的域名，**必须有**——Caddy 靠它签证书 |
| 端口 | 80 与 443 对公网开放（80 用于 ACME 校验与跳转） |

**为什么必须 HTTPS**：浏览器只在安全上下文（`https://` 或 `localhost`）下允许调用摄像头。用 `http://IP:端口` 访问时扫码按钮会直接报错，这是浏览器限制，没有任何绕过办法。

## 2. 首次部署

### 2.1 拉代码

```bash
git clone <你的仓库地址> ~/film-vault
cd ~/film-vault
```

### 2.2 配置环境变量

```bash
cp .env.example .env
```

编辑 `.env`，四项都必须改：

```ini
# 登录 PIN。生产环境不允许 1234，服务启动时会检查并拒绝启动
PIN=你的PIN

# 会话签名密钥。生成：openssl rand -hex 32
# 这个值固定下来，否则每次重启所有设备都要重新登录
SESSION_SECRET=用openssl生成的一串

# 你的域名。DNS 必须已指向本机，否则证书签不下来
SITE_ADDRESS=film.example.com
```

### 2.3 启动

```bash
docker compose up -d
docker compose logs -f app
```

看到 `Server listening at http://0.0.0.0:3300` 即启动成功。首次启动会自动建库并写入 139 条型号库。

Caddy 首次签证书需要几十秒，日志里能看到 `certificate obtained successfully` 之后即可访问 `https://film.example.com`。

### 2.4 初始化数据

浏览器打开 `https://film.example.com`，用 PIN 登录，然后检查：

1. 型号库 → 应有 139 条型号，字母占用表能看到 Kodak / Fujifilm 的占用情况
2. 机身镜头 → 应有预置的 Canon EOS 30V 与 EF 50mm F1.8
3. 建档 → 选一个型号，应能自动带出下一个可用编号

## 3. 日常运维

### 3.1 更新

```bash
cd ~/film-vault
git pull
docker compose up -d --build
```

数据在 `storage/` 卷里，重建镜像不影响数据。启动时会自动应用缺失的数据库迁移。

### 3.2 备份

两种方式，建议都做：

**应用内导出**（推荐，随时可用）

统计页点「备份」，下载 `film-vault-backup-YYYY-MM-DD.zip`。里面是 checkpoint 后的主库 + uploads + 恢复说明。

**整目录复制**（服务器侧）

```bash
# 先 checkpoint，避免复制到写了一半的 WAL
docker compose exec app node -e "
  const D=require('better-sqlite3');
  new D('/app/storage/film-vault.db').pragma('wal_checkpoint(TRUNCATE)')
"
tar czf ~/backup-$(date +%F).tar.gz -C ~/film-vault storage
```

建议加进 crontab，每天凌晨跑一次，保留最近 30 份：

```cron
17 3 * * * cd ~/film-vault && tar czf ~/backups/fv-$(date +\%F).tar.gz storage && find ~/backups -name 'fv-*.tar.gz' -mtime +30 -delete
```

### 3.3 恢复

```bash
docker compose stop app

# 用备份包里的文件覆盖
rm -f storage/film-vault.db-wal storage/film-vault.db-shm
unzip -o film-vault-backup-2026-11-07.zip film-vault.db -d storage/

docker compose start app
```

**必须删掉旧的 `-wal` 与 `-shm`**，否则 SQLite 会用旧日志覆盖恢复进来的数据。

### 3.4 查看日志

```bash
docker compose logs -f app     # 应用日志
docker compose logs -f caddy   # 证书与访问日志
```

## 4. 三端实测清单

部署后必须逐项过一遍，任何一项不过都会影响日常使用。

| 平台 | 检查项 | 关注点 |
|---|---|---|
| iOS Safari | 扫码建档 | Safari 无原生 `BarcodeDetector`，走 WASM polyfill，识别速度会慢一点 |
| iOS Safari | 添加到主屏幕 | 全屏运行、无地址栏，状态栏配色是否协调 |
| 安卓 Chrome | 扫码建档 | 原生 `BarcodeDetector`，应明显快于 iOS |
| 安卓 Chrome | 标签打印 | 系统打印对话框的边距与缩放设置 |
| 鸿蒙浏览器 | 扫码 | 鸿蒙 NEXT 装不了安卓 APK，网页是唯一形态；需确认 WASM 可用 |
| 折叠屏 | 展开/折叠切换 | 布局是否错乱，卡片是否被拉伸 |
| 折叠屏 | 记一笔抽屉 | 展开态下抽屉宽度是否受限 |
| 桌面 | 列表页 | `md` 以上应自动双列 |
| 全平台 | 后台切回 | 切走再回来，进度是否显示为最新 |

### 打印校准

首次打印标签前，先用一张普通纸试打，量一下：

- Code 128 条码的实际宽度（应约 30mm，取决于模板）
- 人眼可读编码的字号（应保证 30cm 距离肉眼可辨）
- 打印对话框里关掉「页眉页脚」、边距设为「无」或「最小」

校准好后记下这套设置，以后每次打印都用同一套。

## 5. 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 服务起不来，日志提示「生产环境必须设置 PIN」 | `.env` 没填 PIN 或仍是 1234 | 改 `.env` 后 `docker compose up -d` |
| 访问域名证书报错 | DNS 未生效，或 80 端口被墙 | `dig 你的域名` 确认解析；确认 80 端口可达 |
| 扫码按钮提示不支持 | 用了 `http://` 访问 | 必须走 `https://` |
| 扫码提示「不支持条码识别」 | WASM polyfill 未加载 | 检查浏览器控制台是否有 CSP 或跨域报错 |
| 所有设备突然掉登录 | `SESSION_SECRET` 每次重启都变 | 在 `.env` 里固定该值 |
| 数据看起来是旧的 | 浏览器 PWA 缓存了旧页面 | 强制刷新，或在设置里清除站点数据 |
| 数据库锁死 | 多进程访问同一 SQLite | 确认只有一个 app 容器在跑 |

## 6. 架构备忘

```
浏览器 ──HTTPS──▶ Caddy ──HTTP──▶ app (Fastify :3300)
                                     ├── SQLite  /app/storage/film-vault.db
                                     └── uploads /app/storage/uploads
```

- 只有一个 app 容器。SQLite 单进程写入，不要水平扩容。
- `storage/` 是唯一的持久化目录，其余都是可重建的。
- 前端静态资源打在 app 镜像里，由 Fastify 直接托管，不单独起 nginx。
